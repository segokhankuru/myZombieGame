# Directory Structure

Four layers, each with one owner tier. If you cannot decide where a file goes, it
probably belongs in a layer you have not thought about yet.

```
design/     what the game is        owner: design tier
docs/       how it is built         owner: engineering, art, QA
config/     every number            owner: systems-designer
Assets/     the Unity project       owner: engineering, art
```

---

## `design/` - the design layer

```
design/
  00-brief.md                 commercial framing, target player, success metrics
  vision.md                   the long-form pitch, kept short
  PILLARS.md                  3-4 pillars, each one line, each testable
  GDD.md                      core loop, mechanics, feature list, feature status
  review-mode.txt             full | lean | solo
  risks.md                    risk register
  systems/
    index.md
    SYS-NN-<slug>.md          one system, one file: intent, rules, states, failure modes
  levels/
    index.md
    LVL-NN-<slug>.md          layout intent, beats, teaching order, blockout spec
  narrative/
    bible.md                  world, characters, tone of voice
    dialogue/                 scene scripts, barks, with localization keys
  economy/
    curves.md                 the shape of every curve and why it has that shape
  ux/
    flows/                    onboarding, menus, HUD states
    input-map.md              every action on every device
    accessibility.md          colour, subtitles, remapping, motion, difficulty
  milestones/
    M-NN-<slug>.md            goal, scope, exit criteria, assignments
  backlog/
    epics/
      EP-NN-<slug>/
        EPIC.md
        story-NNN-<slug>.md   the task packets
    deferred/                 cut, with the reason - this file prevents re-litigation
```

## `docs/` - the technical layer

```
docs/
  CONTEXT.md                  the brain, <=200 lines, read first by everyone
  DECISIONS.md                append-only decision log, <=300 lines
  architecture/
    ARCHITECTURE.md           assemblies, boundaries, data flow, scene graph
    TECH-STRATEGY.md          engine, packages, target hardware, what we will not use
    PERF-BUDGET.md            ms per frame per system, memory, draw calls, load time
    adr/
      index.md
      ADR-NNNN-<slug>.md
  art/
    ART-BIBLE.md              palette, silhouette rules, lighting, reference
    ASSET-BUDGET.md           tri counts, texture sizes, material counts per category
    ASSET-LOG.md              append-only provenance for every generated asset
  audio/
    AUDIO-BIBLE.md            direction, bus map, loudness targets, sfx families
  qa/
    strategy.md               risk-based test strategy
    test-plan.md
    playtests/PT-NN-<slug>.md structured playtest reports
    evidence/<slug>.md        manual verification records
    bugs/BUG-NNN-<slug>.md
    performance/<date>.md     profiler runs against the budget
  ops/
    build.md                  how a build is produced, from a clean machine
    release.md                depots, branches, rollback
  publishing/
    steam-page.md             description, tags, capsule brief, screenshots plan
    beats.md                  announcement, demo, playtest, launch, post-launch
  guides/                     player-facing and contributor-facing docs
```

## `config/` - the tuning layer

See `config-protocol.md`. Nothing here is generated by hand from Unity, and nothing in
Unity is authoritative over it.

```
config/
  schema/<domain>.schema.json   shape, required keys, valid ranges + why
  balance/<domain>.json         the numbers
  content/<domain>.json         instances: items, enemies, levels, upgrades
```

---

## `Assets/` - the Unity project

Full rules in `unity-conventions.md`. Summary:

```
Assets/_Project/
  Code/{Gameplay,Systems,AI,Net,UI,Editor,Tests}   one asmdef each
  Config/     generated ScriptableObjects
  Data/       runtime JSON mirror
  Art/{Concept,Generated,Textures,Sprites,Materials,Models,VFX,UI}
  Audio/{Music,SFX,Mixers}
  Prefabs/{Gameplay,UI,VFX,Net}
  Scenes/{Boot,Menu,Levels,Sandbox}
  Settings/
```

Third-party packages keep their own folders at `Assets/` root and are never edited.

---

## `.state/` - machine state

```
.state/
  project.json        phase, milestone, roster, mode, counters, stack
  gates.jsonl         append-only gate history
  agent-log.jsonl     append-only agent invocation log (token analysis)
  comfy-caps.json     cached ComfyUI capability summary
  comfy-jobs.jsonl    append-only generation history
```

Never hand-edit `.state/`. `/status` and the hooks own it.

## `.claude/` - the studio itself

```
.claude/
  agents/       28 role definitions
  skills/       46 workflows (slash commands)
  rules/        path-scoped coding rules, embedded verbatim into dev prompts
  docs/         the protocols in this folder
  templates/    story, epic, ADR, level spec, playtest report, asset request
  tools/        PowerShell shims - the reason this system is affordable
  comfy/        local generation client, workflows, locked style
  hooks/        session start, write validation, agent logging, YAML guard
```
